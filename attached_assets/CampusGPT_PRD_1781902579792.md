# CampusGPT — Product Requirements Document & UX Blueprint
### A $100B-Quality AI Assistant for Higher Education
*Version 1.0 · Research-Backed PRD distilled from ChatGPT, Claude, Gemini, Perplexity, Genspark, Grok, Copilot, Cursor, Manus, Notion AI, Replit AI, Meta AI*

---

## Executive Summary

CampusGPT is a university-grade AI assistant that combines the **conversational fluency of ChatGPT**, the **citation rigor of Perplexity**, the **artifact workspace model of Claude**, the **agentic execution of Manus/Genspark**, and the **multi-panel IDE patterns of Cursor**, adapted to the unique mental models of university students: timetables, deadlines, advisors, halls, courses, and campus life.

This document is a **build-ready specification**. An engineering team or AI coding agent should be able to construct the application directly from this blueprint.

**Core Bet:** Students don't need another chatbot. They need a calm, trustworthy *campus operating system* that knows their degree, their schedule, their hall, their advisor, and their deadlines — and proves every answer with a source.

## 1. Overall Product Philosophy

### 1.1 Why the leading interfaces feel modern

| Product | Why it feels modern | Pattern to adopt |
|---|---|---|
| **ChatGPT** | Distraction-free single column, generous whitespace, fast streaming, sidebar that disappears on mobile | Center-stage conversation, low chrome |
| **Claude** | Warm serif accent, Artifacts panel that splits *thinking from making*, "extended thinking" collapsible block | Split workspace for outputs that deserve a canvas |
| **Perplexity** | Inline numeric citations `[1][2]`, source rail on the right, "Related" follow-ups below every answer | Citations are first-class, not footnotes |
| **Gemini** | Soft gradients, animated sparkle glyph, generative UI cards (flight cards, hotel cards) | Custom card components per intent |
| **Genspark** | "Super Agent" task plan visible at the top, step-by-step progress checklist | Visible plan = trust |
| **Grok** | Dark cinematic palette, real-time X feed integration, persona switcher | Context-aware data streams |
| **Copilot** | Tightly embedded in host app, side-pane that respects host UI | Be a guest, not a takeover |
| **Cursor** | Three-pane IDE, inline diff suggestions, Cmd-K everywhere | Keyboard-first power user mode |
| **Manus** | Live "computer" window showing the agent's screen as it works | Radical transparency for long tasks |
| **Notion AI** | Slash-command surface, inline transformation, never blocks the page | AI as a verb on existing content |
| **Replit AI** | Agent log + preview + code, three synchronized panes | Show inputs, work, and output simultaneously |

### 1.2 Why users trust these products

1. **Citations & receipts** — Perplexity proved that *every claim with a source* is the single highest-leverage trust mechanism in AI UX. Students will reject any campus AI that "hallucinates" their graduation requirements.
2. **Visible reasoning** — Showing a *summary* of thinking (Claude's "Thought for 12s · 4 steps") without dumping raw chain-of-thought builds confidence without overwhelm.
3. **Reversibility** — Edit, regenerate, branch, delete. Nothing feels permanent.
4. **Predictable streaming** — Tokens arrive at human reading speed; cursors blink; status text updates ("Searching course catalog…" → "Reading PDF…" → "Drafting answer…").
5. **Bounded scope** — The model says "I don't know" or "Let me check with the registrar's page" rather than guessing.
6. **Identity & memory** — "Hi Aisha, here's your Tuesday." Personalization without surveillance vibes.

### 1.3 How they reduce cognitive load

- **One primary action per screen.** The composer is always the gravitational center.
- **Progressive disclosure.** Advanced features hide behind `/`, `@`, or a `+` button.
- **Skeletons, not spinners.** Show the *shape* of the answer before the content arrives.
- **Soft defaults.** New chat opens with 3–4 suggestion chips, not a blank stare.
- **Consistent vertical rhythm.** Every assistant turn follows the same anatomy: header → body → citations → actions.

### 1.4 Shared design principles (the canon)

1. **Conversation is the chrome.** The chat thread is the navigation; UI panels are accessories.
2. **Transparent agency.** The user must always know *what the AI is doing, on whose behalf, with which data*.
3. **Latency is a UI problem, not an engineering problem.** Stream, skeleton, summarize.
4. **Multimodal by default.** Voice, image, file, link — all enter through the same composer.
5. **Stateless looks, stateful brains.** The interface looks light; the system remembers heavily.
6. **Keyboard parity.** Every mouse action has a shortcut (`⌘K`, `⌘/`, `⌘↵`, `Esc`).
7. **Quiet motion.** Animations are 150–250 ms, ease-out, never bouncy in productivity contexts.

│            │  Composer: @ mentions, / commands, +     │              │
└────────────┴──────────────────────────────────────────┴──────────────┘
```

- **Pattern source:** ChatGPT (left rail) + Claude (right artifact panel) + Cursor (three-pane).
- **Default state:** Left sidebar open, right context panel **closed** until invoked (mention of a doc, artifact, or plan).
- **Sidebar:** 280 px, collapsible to 56 px icon rail (`⌘\`).
- **Right panel:** 360 px default, drag-resizable 320–520 px.
- **Chat column:** Fixed `max-width: 760px`, centered. This is the most-copied number in the industry — it's the reading comfort sweet spot.

### 2.2 Mobile Layout (< 768 px)

- **Single column**, full-bleed chat.
- **Top bar (56 px):** ☰ (drawer) · thread title (truncated) · ⋯ (overflow).
- **Bottom composer (sticky, safe-area aware):** mic on the left, attach `+`, send arrow on the right.
- **Drawer (hamburger):** Slides in from left, 80% width, with backdrop scrim at `rgba(0,0,0,0.4)`.
- **No right panel.** Artifacts and sources become a **bottom sheet** that drags up over the chat. Threshold: 30% → snap to 60% → snap to 92%.
- **Voice button is prominent** — a 56 px FAB-style mic on the composer left, because phones are voice-first devices.

### 2.3 Responsive breakpoints

| Breakpoint | Behavior |
|---|---|
| `≥ 1280 px` | Sidebar + chat + right panel (when invoked) |
| `1024–1279 px` | Sidebar + chat; right panel becomes overlay drawer |
| `768–1023 px` | Sidebar collapses to icon rail; chat full width |
| `< 768 px` | Mobile layout (drawer + bottom sheet) |

### 2.4 Navigation patterns

- **Persistent left sidebar** for navigation (top-level destinations).
- **Top bar** for *contextual* actions on the current thread (model, share, export).
- **Right panel** for *generated context* (sources, artifacts, plans).
- **Command palette (`⌘K`)** as universal escape hatch — jump to thread, switch model, open doc, ask anything.
- **Slash menu (`/`)** in the composer for actions ("/summarize", "/plan-semester", "/find-room").
- **Mention menu (`@`)** to scope context ("@CS3243-syllabus", "@advisor", "@hall-handbook").

### 2.6 Hamburger menu (mobile)

Identical IA to sidebar, but with three additions:
1. **Big search bar at top** (mobile users type, they don't ⌘K).
2. **Recently used quick row** — 4 horizontal pills of recent chats.
3. **Bottom-pinned profile + logout** within the drawer to keep thumb reach.

### 2.7 Multi-panel layouts

**Trigger rules** (when to open the right panel):
- User uploads a document → "Document" tab with PDF viewer.
- AI generates an artifact (table, study plan, code, slide) → "Artifact" tab.
- AI answers with sources → "Sources" tab with full citation cards.
- AI executes a multi-step task → "Plan" tab with checklist.
- User opens timetable inline → "Timetable" tab.

Each tab is **shareable as a deep link** and **persists across sessions**.

### 2.8 Workspace structure

CampusGPT is organized into **Spaces**:
- **My Campus** (default) — personal threads + planner.
- **Academic** — course-scoped chats (one per active module).
- **Career** — internships, CV, interview prep.
- **Wellness** — non-clinical wellbeing chats (with safety guardrails).
- **Shared** — group projects (multi-user threads).

Spaces are *visual containers*, not separate apps — they re-color the header accent and pre-load relevant tools, mimicking how Notion uses workspaces.

## 3. Chat Experience

### 3.1 Message styling — first principles

- **No bubbles for the assistant.** ChatGPT, Claude, and Perplexity have all converged on **bubble-less assistant messages** because bubbles cap line length and feel like SMS. Use bubbles only for user messages.
- **User messages** = rounded rectangle, brand-tinted background (`bg-brand-50`), right-aligned, max-width 75%.
- **Assistant messages** = no background, left-aligned, full column width (760 px), with a **subtle avatar dot** at top-left.
- **Inter-message spacing** = 32 px vertical.
- **Within-message rhythm** = 16 px paragraph spacing, 24 px before headings.

### 3.2 User message design

```
                              ┌──────────────────────────────────┐
                              │ Can you help me plan my Sem 2    │
                              │ around my morning lab on Tues?   │
                              │ [attached] timetable.pdf         │
                              └──────────────────────────────────┘
                                                       12:43  ✎ ↻
```

- Background: `--surface-user` (brand-50 in light, brand-900/30 in dark).
- Border-radius: 18 px on three corners, 6 px on bottom-right (the "tail" implication, no actual tail SVG).
- **Edit and resend** appear on hover: pencil icon + circular arrow. Editing replaces the message inline and re-runs from that point (ChatGPT pattern), pruning later turns into a *branch* selector.

### 3.3 Assistant message design (anatomy)

```
●  CampusGPT  ·  GPT-Campus-Pro  ·  Thought for 6s ▾
   ────────────────────────────────────────────────
   Here's a plan for your Sem 2 that respects your
   Tuesday 8–11am lab.

   **Recommended schedule**
   • Mon 10am — CS2103
   • Tue 1pm  — CS2106                         [1]
   • Wed 9am  — MA2104
   ...

   ┌─ Sources ─────────────────────────────────┐
   │ [1] NUS Course Catalog AY26/27, p. 142    │
   │ [2] CS2106 module page, accessed today    │
   └────────────────────────────────────────────┘

   👉 Related: "Generate ICS file" · "Add to planner" · "What if CS2106 clashes?"

   👍 👎 ⧉ ↻ ⤴
```

**Header row** (12 px, muted):
- Avatar dot (8 px, brand gradient).
- Name (`CampusGPT`).
- Model chip (`GPT-Campus-Pro`) — clickable to switch.
- Reasoning summary (`Thought for 6s ▾`) — Claude pattern, expandable.

**Body**:
- Markdown rendered with KaTeX for math, syntax-highlighted code with Shiki, and **inline citation pills** (`[1]`) that are hover-previewed and click-pinned.

**Footer actions** (visible on hover, sticky on mobile):
- Thumbs up / down → feedback modal.
- Copy.
- Regenerate (long-press for "Regenerate with…" → model picker).
- Share / export.

### 3.4 Streaming responses

- **Token-by-token streaming** with a blinking cursor `▍` at the tail.
- **Stop button** replaces send during stream — full-width visibility on mobile.
- **Smart chunking:** complete Markdown tokens before rendering (don't render half a code fence).
- **Speed throttle:** Cap rendering at ~80 tokens/sec so streams feel readable, not jittery. (This is OpenAI's quiet default.)
- **Auto-scroll lock:** If user scrolls up during stream, *don't* yank them back. Show a floating "↓ Jump to latest" pill instead (ChatGPT, Claude pattern).

### 3.5 Typing indicator vs Thinking indicator

These are **two different things** — most products conflate them and lose user trust.

| State | Visual | When |
|---|---|---|
| **Connecting** | Three pulsing dots `· · ·` | First 0–800 ms while request is in flight |
| **Thinking** | Shimmer text "Thinking…" with subtle pulse | Reasoning model, before tokens stream |
| **Searching** | Tool chip: 🔎 "Searching course catalog…" | Tool call in progress |
| **Reading** | Tool chip: 📄 "Reading syllabus.pdf (12 pages)" | File processing |
| **Drafting** | Cursor `▍` blinks at end of stream | Tokens are arriving |
| **Done** | Cursor disappears, footer actions fade in | Stream complete |

### 3.6 Reasoning displays (the Claude/o1 pattern)

When using a reasoning model, show:

```
▾ Thought for 12 seconds · 5 steps
   1. Identified user is asking about Sem 2 planning
   2. Recalled their Tuesday lab constraint from earlier
   3. Cross-referenced CS module timings…
   4. Checked for clashes
   5. Drafted recommendation
```

**Rules:**
- Collapsed by default; show summary line only.
- Expand reveals **paraphrased steps**, not raw chain-of-thought. Raw CoT can leak training artifacts, be wrong-but-confident, and confuse users.
- Steps stream in as the model reasons (visible progress builds trust during long thinks).
- Max 5–7 visible steps; collapse middle steps with "+3 more" if longer.

### 3.7 Citations & source attribution

**Inline citations** = numbered pills `[1]`, `[2]`. Hover shows a preview card:

```
┌─────────────────────────────────┐
│ NUS Course Catalog 26/27        │
│ Page 142 · CS2106 prerequisites │
│ accessed 2 min ago              │
│ [Open in panel →]               │
└─────────────────────────────────┘
```

**Source card** (in right panel):
- Favicon or doc icon.
- Title.
- Domain or doc path.
- Relevant excerpt (highlighted).
- "Open original" button.
- Timestamp of retrieval.

**Rules:**
- Every factual claim about courses, regulations, deadlines, or campus facts **must** carry a citation.
- If no citation available, prepend: *"I'm not certain — please verify with your advisor."*
- Citation numbering is **per-message** (resets each turn), like Perplexity.

### 3.8 Follow-up suggestions

After every assistant turn, show 3 chip-shaped follow-ups:

```
👉 [Generate ICS file]  [Add to planner]  [What if CS2106 clashes?]
```

- Generated by a lightweight model from the conversation state.
- Tappable to insert into composer (don't auto-send — let users edit).
- Max 3 on desktop, 2 on mobile.
- Replaced by new suggestions after each turn (don't pile up).

## 4. AI Reasoning UX — What to show, what to hide

### 4.1 The hierarchy of transparency

```
       VISIBLE & EMPHASIZED
       ────────────────────
       • What I'm doing right now ("Searching catalog…")
       • What I've finished ("Read 3 pages of syllabus.pdf")
       • Sources I used (citation cards)
       • Tools I have access to (mentioned in onboarding + /commands)

       VISIBLE BUT COLLAPSED
       ─────────────────────
       • Step-by-step reasoning summary (Claude "Thought for…")
       • Full source list (right panel, on demand)
       • Tool call details (click chip to expand JSON)

       HIDDEN
       ──────
       • Raw chain-of-thought tokens
       • System prompts
       • Internal tool retries / errors that resolved
       • Embedding queries, vector scores
```

### 4.2 Thinking

- **Reasoning models:** Show "Thinking…" shimmer + step counter.
- **Non-reasoning models:** Skip — go straight to streaming.
- **Long thinks (>10s):** Show *what is being considered* in plain English ("Considering your Tuesday lab constraint…").

### 4.3 Searching

```
🔎 Searching campus knowledge base
   └─ Query: "CS2106 prerequisites 2026"
   └─ Found 4 results
```

- Chip animates with a left-to-right shimmer while in progress.
- Click the chip to expand the query and result count.
- After completion, the chip stays as a permanent provenance marker.

### 4.4 Reading documents

```
📄 Reading "syllabus_cs2106.pdf"
   ▓▓▓▓▓▓▓▓▓▓▓▓▓░░░░  12 / 18 pages
```

- Linear progress bar (preferred over circular for predictability).
- Time estimate appears only after 3 seconds and only if estimate is reliable.
- For images: 🖼 "Analyzing image (1 of 2)…"

### 4.5 Analyzing files

For spreadsheets / structured data:

```
📊 Analyzing grades.xlsx
   • 3 sheets detected
   • 247 rows in "Sem 1"
   • Computing GPA distribution…
```

Always tell the user *what shape the data is* before showing conclusions — this is how Genspark and Manus build trust.

### 4.6 Browsing sources

When the AI consults external sources (NUS website, etc.):

```
🌐 Visited 4 pages
   • nus.edu.sg/registrar/calendar
   • nus.edu.sg/cs2106
   • +2 more
```

Click expands to full URL list with timestamps.

### 4.7 Tool usage

Every tool call is rendered as a **labeled chip** with three states:
- **Running:** shimmer + "Doing X…"
- **Success:** check + "Did X · 2.3s"
- **Failure:** ! + "Couldn't do X — retrying / abandoning"

**Never silently fail.** If a tool fails, surface it — students respect honesty more than they punish errors.

### 4.8 Long-running tasks (the Manus / Genspark pattern)

For tasks that take >30 seconds (e.g., "Plan my entire semester and book my consultations"):

1. **Plan preview** — assistant shows a checklist of steps *before* executing, asks "Proceed?"
2. **Live execution panel** opens on the right with:
   - Step checklist (✓ done, ⏳ in progress, ⏸ queued).
   - Live activity log ("Opened NUS Edurec…", "Selected CS2106…").
   - Estimated time remaining.
   - Pause / Cancel buttons (always reachable).
3. **Notification on completion** — toast + sound (subtle, ≤ -20 dBFS).
4. **Summary** — final assistant message recaps what was done, with deep links to each artifact.

### 4.9 Best practices & trust mechanisms

| Practice | Why |
|---|---|
| Always cite | Without citations, no trust survives the first wrong answer. |
| Always summarize reasoning | Raw CoT confuses; summaries reassure. |
| Always show tools | Hidden tools feel like surveillance. |
| Always allow pause | Agency is non-negotiable in agentic flows. |
| Always confirm destructive actions | "I'll register you for CS2106 — confirm?" |
| Never fake progress | Fake progress bars destroy trust on first detection. |

## 5. Voice Experience

### 5.1 Research summary

| Product | Voice model | Latency | Interruptible |
|---|---|---|---|
| ChatGPT Advanced Voice | Realtime API (speech-to-speech) | ~320 ms | Yes, full duplex |
| Gemini Live | Native multimodal | ~400 ms | Yes |
| Grok Voice | xAI native | ~500 ms | Partial |
| Claude (no native voice) | — | — | — |

The bar is now **sub-500 ms latency, true full-duplex** (you can interrupt the AI mid-sentence, like a human conversation).

### 5.2 Voice input

- **Push-to-talk** (hold space bar on desktop, hold mic button on mobile) — for noisy environments and intentional commands.
- **Tap-to-talk** — single tap starts/stops; default for casual use.
- **Wake word** — *not recommended* for v1 (privacy concerns on campus, false-positive fatigue).
- **Live transcript** appears above the composer as you speak, with confidence-based gray-out for uncertain words.

### 5.3 Voice output

- TTS streams **alongside text** — students can mute the voice while reading, or hide the text while listening.
- **Two voices**: a neutral default and one localized option (e.g., regional accent appropriate to the campus).
- **Speed control** (0.8× / 1× / 1.25× / 1.5×) in the voice overlay.
- **Punctuation-aware pacing** — small pauses on commas, larger on periods.

### 5.4 Realtime conversations (the headline feature)

**Voice Mode overlay** (full-screen on mobile, large modal on desktop):

```
                    ◉
                ╭───────╮
               (    ●    )    ← Animated orb
                ╰───────╯
                
            "Listening…"
       (or live caption of AI speech)

         [End]   [Mute]   [Keyboard]
```

- Orb pulses with audio amplitude (in + out).
- Background subtly shifts color: cool blue while listening, warm gold while AI speaks.
- Live closed captions toggle.
- **Interrupt by speaking** — the AI halts within 200 ms.
- **Visual hint when AI is "thinking"** — orb does a slow rotation instead of pulse.

### 5.5 Full duplex behaviors

- **Interruption (barge-in):** User speech instantly mutes AI output; the AI processes the interruption.
- **Backchannels:** Brief "mhm", "got it" from the AI during user pauses make the conversation feel natural (Gemini Live does this beautifully).
- **Turn-taking signals:** A subtle haptic on mobile when it's the user's turn.

### 5.6 Ideal Voice UX for CampusGPT

1. **One-tap "Walk to class" mode.** Voice + GPS + calendar. As the student walks, CampusGPT reads upcoming reminders, weather, and answers questions hands-free.
2. **Lecture mode** (passive listening with consent) — student taps "Start lecture transcript", CampusGPT transcribes + summarizes. **Mandatory ethical guardrail:** lecturer consent prompt, local processing toggle, auto-delete after N days.
3. **Drive-thru advising** — a 3-minute spoken Q&A flow for quick registrar-style questions ("Am I on track?", "What's my GPA?", "When is reading week?").
4. **Multilingual voice** — switch language without leaving voice mode (critical for international students).
5. **Privacy-first defaults** — voice transcripts default to *not* training the model; clear "delete voice history" affordance.

## 6. Document Intelligence Experience

### 6.1 Upload flow

```
[+] → Upload from device
      Upload from Drive / OneDrive
      Paste link
      Take photo (mobile)
      Scan document (mobile)
```

**Drag-and-drop** the file anywhere on the chat area — the entire area shows a dashed border + "Drop to attach" message. Multi-file supported (up to 10).

### 6.2 Supported formats (Tier 1)

PDF, DOCX, PPTX, XLSX, CSV, MD, TXT, PNG, JPG, HEIC, MP3, MP4, ICS (calendar).

### 6.3 Processing states (the journey)

| State | Visual | Duration |
|---|---|---|
| **Uploading** | File chip with progress ring | 0–3s |
| **Parsing** | "Parsing PDF…" with shimmer | 1–4s |
| **Indexing** | "Indexing 24 pages…" with linear bar | 2–10s |
| **Ready** | Green dot + page count | — |
| **Failed** | Red dot + retry button + reason | — |

The file chip is **persistent** — it stays visible in the message thread as a small card, hover preview, click opens the document panel.

### 6.4 Reading states

When the AI is consulting the document during a later turn:

```
📄 Reading "AY26-27_handbook.pdf"
   └─ Focused on pages 12, 14, 38
   └─ Extracted: graduation requirements
```

The PDF viewer in the right panel **auto-highlights** the cited passages.

### 6.5 Extraction states

For structured extraction (e.g., "extract all deadlines from this syllabus"):

1. **Detection chip:** "Found 12 dates, 4 assignments, 1 final exam."
2. **Preview table:** Inline collapsible table with confidence per row.
3. **Confirm action:** "Add 4 deadlines to your planner?" → confirm → write.

### 6.6 Citation & referencing system

CampusGPT uses a **two-tier citation system**:

**Tier 1 — Web/Catalog citations:** `[1]`, `[2]`, footnote pills with hover previews.

**Tier 2 — Document citations:** `[doc:syllabus.pdf p.12]` — clicking jumps the right-panel PDF viewer to that page with a yellow highlight.

When mixed:
```
The capstone counts for 12 MCs [1][doc:handbook.pdf p.38].
```

### 6.7 Document panel (right side, when a doc is active)

```
┌─ syllabus.pdf · 24 pages ───────┐
│  [< 12 / 24 >]   🔍  ⤓  ⋯       │
├──────────────────────────────────┤
│                                  │
│       [PDF viewer canvas]        │
│       with highlight overlays    │
│                                  │
├──────────────────────────────────┤
│ Pages cited in this thread:      │
│ • p.12 (used in turn 3)          │
│ • p.38 (used in turn 5)          │
└──────────────────────────────────┘
```

- Search-in-document with `⌘F` scoped to the panel.
- Annotations: highlight + add note (saved to the thread).
- **Two-way linking:** click a citation in chat → PDF jumps; click a highlight in PDF → chat scrolls to the citing message.

### 6.8 Special handling

- **University regulations / handbooks:** Detected by filename + content heuristics → automatically tagged "Regulation" → answers grounded in these documents get a **shield badge** indicating high-confidence sourcing.
- **Course catalogs:** Parsed into a structured graph (module → prereq → MCs → semester offered). Enables structured queries: "Show all 4 MC modules in Sem 2 with no prereqs."
- **Timetable PDFs:** Auto-extracted to ICS; offered as a one-click import.
- **Handwritten notes / whiteboards:** Vision model transcribes; user confirms.

## 7. CampusGPT-Specific Opportunities

These are the features that **no general AI has**, and that turn CampusGPT from a chatbot into a campus operating system.

### 7.1 Academic advising

- **My Path** dashboard: degree progress as a vertical track (modules completed → in progress → required → recommended).
- **What-if simulator**: "What if I switch to Data Science specialization?" — recomputes the path live.
- **Advisor handoff**: "Book a 15-min slot with Prof. Tan" → opens advisor's calendar integration with pre-filled context summary.

### 7.2 Degree planning

### 8.1 Information architecture (final)

➕ New Chat                              Always one tap away (⌘N)
🔍 Search                                ⌘K palette
─────────────────────────────────────────────────────────────
📌 PINNED                                User-curated, surfaces first
   • [up to 5 user-pinned threads]
─────────────────────────────────────────────────────────────
🕐 RECENT                                Auto, 7-day window
   • [chronological]
   See all →                             Goes to full history view
─────────────────────────────────────────────────────────────
⭐ SAVED                                 Bookmarked replies / threads
─────────────────────────────────────────────────────────────
MY CAMPUS                                Section header
🏛  Campus Knowledge                     Curated KB: regulations, handbooks
📚 Documents                  (12)       Personal uploads
🎓 Academic Planner                      Path + simulator
🗓  Timetable                            This-week view
🎉 Events                      (3)       Personalized feed
🔔 Notifications               (5)       Reminders + system msgs
─────────────────────────────────────────────────────────────
TOOLS                                    Section header
🎙  Voice Mode                           Opens overlay
🧭 Campus Map                            Wayfinding
📨 Inbox Integration                     Optional, opt-in email scan
─────────────────────────────────────────────────────────────
⚙  Settings
[Avatar] Profile · Plan badge            Bottom-pinned
```

### 8.2 Hierarchy rationale

- **Primary actions (New Chat, Search) sit alone at top** — never buried under sections.
- **Pinned > Recent > Saved** — pinned items represent active, top-of-mind work; recent is auto; saved is archive.
- **"My Campus" section** is the heart of differentiation — these are the destinations a general AI doesn't have.
- **Tools** are *modes* (entering voice mode, opening map) rather than destinations.
- **Settings + Profile** at the bottom — visual anchoring, thumb-reachable on mobile.
- **Badge counts** appear only on Documents, Events, Notifications — and only when there's a real, actionable new item (no vanity badges).

### 8.3 Placement principles

| Principle | Application |
|---|---|
| **Frequency drives placement** | New Chat is at the top because it's used many times daily. |
| **Recency matters, but is bounded** | "Recent" shows last 5; "See all" handles the long tail. |
| **Group by mental model, not by feature** | Documents + Campus Knowledge live together because they're both "stuff I read". |
| **Counts only when they imply action** | "3 events match you" yes; "147 threads" no. |
| **Bottom = identity** | Profile/settings live at the bottom, never compete with content. |

## 9. Premium Microinteractions

The patterns that separate a $100M product from a $100B product are *almost entirely in the micro-layer*. Here are the exact specs.

### 9.1 Animation tokens

| Token | Value | Use |
|---|---|---|
| `motion/duration/instant` | 80 ms | Hover-color, tooltip |
| `motion/duration/fast` | 150 ms | Most UI transitions |
| `motion/duration/normal` | 220 ms | Panel open/close |
| `motion/duration/slow` | 320 ms | Page transitions, modal enter |
| `motion/easing/standard` | `cubic-bezier(0.2, 0, 0, 1)` | Default for entrances |
| `motion/easing/exit` | `cubic-bezier(0.3, 0, 1, 1)` | Default for exits |
| `motion/easing/spring` | spring(stiffness=300, damping=30) | Voice orb, message arrival |

Never use bounce in a productivity tool. Bouncy = playful = not premium.

### 9.2 Hover states

- **Buttons**: background lightens by 4%, scales 1.00 (no scale on click in productivity UIs — only in marketing).
- **Cards**: 1 px border becomes brand-300, shadow elevates from `sm` to `md`, 150 ms ease-out.
- **Citations `[1]`**: pill background shifts to brand-100, preview card fades in after 200 ms hover delay (prevent jumpiness on accidental hover).

### 9.3 Loading states (skeletons over spinners)

For known shapes, **show the shape**:

```
┌─────────────────────────────┐
│ ▒▒▒▒▒▒▒▒▒▒▒▒▒▒              │  ← title shimmer
│ ▒▒▒▒▒▒▒▒▒▒                  │
│                             │
│ ▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒  │
│ ▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒      │  ← body shimmer
│ ▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒▒          │
└─────────────────────────────┘
```

- Shimmer: linear gradient sweep, 1.5 s loop, opacity 0.04 → 0.08 → 0.04.
- Use spinners **only** when shape is unknowable (initial app load, voice processing).

### 9.4 Skeleton screens — when to use which

| Scenario | Use |
|---|---|
| Chat thread loading | Message skeletons (user + assistant alternating) |
| Document opening | Page frame skeleton with shimmer |
| Sidebar list loading | Three thread-row skeletons |
| Voice mode entering | Crossfade, no skeleton (overlay is fast) |
| Streaming reply | No skeleton — the cursor *is* the loading state |

### 9.5 Transitions (page-level)

- **Thread switch**: Crossfade 220 ms; preserve scroll position per thread.
- **Sidebar collapse**: Width animates 220 ms; icons fade at 80 ms inside the transition.
- **Right panel open**: Slide-in from right, 220 ms `motion/easing/standard`; chat column shrinks proportionally.
- **Voice overlay**: Scale-up from mic button origin (0.92 → 1.0), opacity 0 → 1, 280 ms.
- **Modal enter**: Backdrop opacity 0 → 0.4, modal scale 0.96 → 1.0 + opacity 0 → 1, 220 ms.

### 9.6 Sound design

- **Default OFF.** Sounds are off by default; opt-in in settings.
- When on, four sounds only:
  - **Send** — very subtle "tick" (-24 dBFS, 80 ms).
  - **Reply complete** — soft "chime" (-20 dBFS, 220 ms).
  - **Notification** — distinct "ding" (-18 dBFS, 320 ms).
  - **Error** — low "thud" (-22 dBFS, 180 ms).
- Designed by a sound designer (not stock). Each sound shares a tonal family (e.g., all in F major).

### 9.7 Empty states

Empty states are *opportunities*, not failures.

**Empty Home (new user):**
```
        ✨  Welcome to CampusGPT
        
        Your campus, in conversation.

  ┌──────────────────┐  ┌──────────────────┐
  │ 🎓 Plan my       │  │ 📅 What's my     │
  │    semester      │  │    week look like│
  └──────────────────┘  └──────────────────┘
  ┌──────────────────┐  ┌──────────────────┐
  │ 📄 Upload my     │  │ 🏛  Tell me about │
  │    syllabus      │  │    King Edward VII│
  └──────────────────┘  └──────────────────┘
```

**Empty Documents:**
```
    📚
    No documents yet.
    
    Drag a PDF here, or [Upload]

```

**Empty Events:**
```

```

### 9.8 Premium "tells" (the small things)

- **Composer expands** as the user types: 1 line → grows to max 8 lines, then scrolls inside. Smooth height animation.
- **Drag-attach** shows a faint dashed border on the *whole chat area*, not just the composer.
- **Selecting text in an AI reply** pops a toolbar: "Copy · Ask follow-up · Quote in new chat · Save as note" — like Notion's selection menu.
- **`⌘+C` on no selection** copies the last assistant message (delightful).
- **Long-press regenerate** = "Regenerate with [model picker]".

## 10. AI Personality & Response Style

### 10.1 Persona definition

> **CampusGPT is the senior who knows everything, has time for you, and never makes you feel small for asking.**

- **Friendly**, not chummy.
- **Confident**, not arrogant.
- **Concise**, not curt.
- **Encouraging**, not patronizing.
- **Respectful of student stress** — never minimize ("Don't worry, exams are easy!").

### 10.2 Tone matrix

| Context | Tone |
|---|---|
| Academic question | Warm, precise, cited |
| Deadline reminder | Direct, supportive, action-oriented |
| Career advice | Reflective, asks questions back |
| Wellness signals | Gentle, never diagnostic, always offers human resources |
| Casual chat | Playful, light, with light campus humor |
| Errors | Honest, brief, with a path forward |

### 10.3 Voice & language rules

- **First person singular** ("I") for the assistant.
- **Second person** ("you"), never "the user".
- **Plain English first**, technical terms second with brief gloss on first use.
- **Sentences under 24 words** in default replies.
- **No emoji in factual replies**; light emoji in casual / encouragement replies (max 1 per message).
- **Localized to campus vocabulary** ("module" vs. "course", "semester" vs. "term", "hall" vs. "dorm") — configurable per institution.

### 10.4 Reply structure (the canonical anatomy)

```
[Direct answer in 1–2 sentences]

[Supporting detail with citations, bulleted if >3 points]

[1 caveat or clarification if needed]

[Optional: 1 light follow-up question OR 3 chip suggestions]
```

**Length defaults:**
- Quick fact: 1–3 sentences.
- Explanation: 1 short paragraph + bullets.
- Plan / strategy: structured headings + bullets.
- Never use heading-heavy formatting for short answers.

### 10.5 Academic accuracy rules

1. **No hallucinated regulations.** Every rule statement carries a `[doc:...]` citation. If no source: "I don't have this in my knowledge — please check with the registrar."
2. **Grades, GPAs, requirements are stated with the source year.** "Per AY26/27 handbook…"
3. **Always show uncertainty** when present. "I'm 80% sure — verify with your advisor before deciding."
4. **Refuse to give legally binding advice.** Visa, immigration, medical: hand off to humans.

### 10.6 Conciseness rules

- **Lead with the answer**, not with throat-clearing ("Great question!", "Sure, I can help with that!").
- **Default to short** unless the user signals depth ("explain thoroughly", "I'm new to this").
- **Bullet only when 3+ items**, otherwise prose.
- **Code blocks only for code, commands, or precise paths.**

### 10.7 Citations style

- Inline numeric pills `[1]` for web / catalog.
- Inline `[doc:filename p.X]` for uploaded docs.
- One source per claim is enough; more than 3 sources per sentence is overkill.

### 10.8 Follow-up suggestions

- **Always** offer 1–3 follow-ups except in:
  - Pure acknowledgments ("Got it!").
  - Wellness conversations (let the student lead).
  - When the answer is genuinely terminal.

### 10.9 Error handling

```
I couldn't reach the course catalog just now — looks like
the server is slow. Want me to retry, or use what I last
loaded (cached 2 days ago)?

[Retry]   [Use cached]   [Skip]
```

- **Name the failure** ("I couldn't reach…").
- **Explain in human terms** (no stack traces).
- **Offer 2–3 next actions.**
- **Never lose the user's input** — the typed message is preserved.

### 10.10 Clarification questions

Ask only when:
- The question is **ambiguous in a way that changes the answer materially**.
- A wrong assumption would cost the student time / money / opportunity.

Otherwise, **make the most likely assumption, state it, and proceed**:
> *"I'll assume you mean Sem 2 of AY26/27 — let me know if you meant something else."*

Never start with: *"What do you mean by…?"* That's a UX failure. Make a confident guess, label it as a guess, and answer.

- **Color**: never the sole carrier of meaning (icons + labels accompany color).
- **Touch targets**: ≥ 44 × 44 px.
- **Font scaling**: layout reflows up to 200% without horizontal scroll.
- **High contrast mode**: respect OS-level high-contrast setting.
- **Voice mode** ships with **always-on captions toggle** for deaf/HoH students.
- **Forms** have explicit `<label>` association.
- **Errors** announced via `role="alert"`.

| Catalog drift | Daily KB refresh + diff alerts; year-stamped citations |
| Voice mode misuse in lectures | Lecturer consent prompt; on-device processing option |

### 12.10 Final design north star

> *Every screen should feel like a calm, knowledgeable senior is sitting next to the student, pointing at the right thing, citing the right source, and gently nudging them toward the next right action.*

If a design decision doesn't serve that sentence, it doesn't ship.

## Appendix B — Glossary

- **Artifact**: A structured output (table, plan, code) that gets its own panel rather than living inline.
- **Composer**: The input area where the user types / speaks / attaches.
- **Provenance**: The traceable origin of any AI claim — source + retrieval timestamp.
- **RAG**: Retrieval-Augmented Generation — combining LLM with a knowledge base.
- **Reasoning model**: An LLM that performs explicit multi-step thinking before answering.
